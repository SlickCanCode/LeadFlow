# LeadFlow Backend API

This guide describes the HTTP endpoints currently exposed by the backend, including request/response shapes and examples. Endpoints use JSON unless noted; replace `{baseUrl}` with the deployed backend origin (for example, `http://localhost:8080` in a local run).

## Conventions

- API prefix: `/api/v1`.
- Send JSON requests with `Content-Type: application/json`.
- IDs are UUID strings. Timestamps are ISO-8601 strings.
- Successful JSON errors use `{"errors":["message"]}`. Validation and malformed-body errors return `400`; missing organizations return `404`; duplicate/conflicting resources and missing business settings return `409`; unavailable AI services return `503`; unexpected errors return `500`.
- Spring Security permits unauthenticated `POST` requests only to the web-chat and contact-form message endpoints. Other API routes, including organization setup, manual leads, one-off messages, and the WhatsApp webhook, are denied until an authentication policy is implemented. Provision initial organizations through a trusted deployment process, not by exposing setup endpoints.
- Browser CORS for `/api/v1/**` is configured with `APP_CORS_ALLOWED_ORIGINS` (defaults to `http://localhost:3000`). Set it to the exact production frontend origin(s); do not use `*`. The unauthenticated `/actuator/health` check is an exception and allows cross-origin GETs from any site without credentials. CORS is not authentication: non-browser clients can still call the two public message routes, so enforce abuse controls at the deployment edge before public launch.

## Endpoints

### Health

`GET /actuator/health`

Returns the application health status without exposing health details. It is available without authentication and allows browser requests from any origin.

### Messages

#### Send a one-off message

`POST /api/v1/message/send`

Request type: `MessageRequest`. The organization must exist and have organization settings configured.

```json
{
  "organizationId": "8b5d27f2-27d7-4a49-86d5-252d9c51a7a4",
  "message": "What services do you offer?"
}
```

Both fields are required; `message` must not be blank.

#### Send a web-chat message

`POST /api/v1/message/web-chat/send`

Request type: `WebChatMessageRequest`. An existing lead is reused for the same organization and `externalId`; otherwise, a website-chat lead is created. The message exchange is recorded in the conversation history.

```json
{
  "organizationId": "8b5d27f2-27d7-4a49-86d5-252d9c51a7a4",
  "externalId": "landing-page-visitor-123",
  "message": "Can I book a consultation?"
}
```

All fields are required and non-blank. `externalId` is limited to 255 characters and should be a stable visitor identifier chosen by the frontend. The organization must have settings configured.

#### Send a contact-form message

`POST /api/v1/message/contact-form/send`

Request type: `ContactFormMessageRequest`. This creates a lead from the submitted name and email, then records the inbound message and AI response.

```json
{
  "organizationId": "8b5d27f2-27d7-4a49-86d5-252d9c51a7a4",
  "name": "Alex Morgan",
  "email": "alex@example.com",
  "message": "Please contact me about your services."
}
```

All fields are required and non-blank. `email` must be a valid email address (maximum 255 characters). `name` must fit the lead's first- and last-name fields (maximum 100 characters per part; maximum 201 overall). The organization must have settings configured.

Each of the three message endpoints returns `200 OK` with `MessageResponse`:

```json
{
  "response": "We offer several services...",
  "provider": "google",
  "model": "gemini-2.5-flash"
}
```

`provider` and `model` identify the selected AI provider and model. Their exact values depend on server configuration.

### Organizations and leads

These endpoints create/configure backend records. They are generally setup or administrative operations, not public landing-page form endpoints.

#### Create an organization

`POST /api/v1/organization`

Request type: `CreateOrganizationdto`.

```json
{
  "name": "Acme Consulting",
  "email": "hello@acme.example",
  "phone": "+1-555-0100",
  "address": "123 Main Street",
  "logoUrl": "https://acme.example/logo.png",
  "timezone": "Europe/London",
  "currency": "GBP"
}
```

Only `name` is required. `email`, `phone`, `address`, `logoUrl`, `timezone`, and `currency` are optional; currency, when provided, must be a three-letter code. The returned slug is generated by the backend.

Returns `201 Created` with `OrganizationResponse`, containing the organization ID and saved organization data.

#### Update an organization

`PUT /api/v1/organization/{organizationId}`

Request type: `CreateOrganizationdto` (the same validated shape as organization creation). `name` is required; send the complete organization representation. Omitted optional contact/address/branding fields are cleared, and omitted `timezone`/`currency` use the defaults `UTC`/`USD`. The backend regenerates the slug from the new name and ensures it is unique.

```json
{
  "name": "Acme Consulting Ltd",
  "email": "hello@acme.example",
  "phone": "+1-555-0100",
  "address": "123 Main Street",
  "logoUrl": "https://acme.example/logo.png",
  "timezone": "Europe/London",
  "currency": "GBP"
}
```

Returns `200 OK` with the updated `OrganizationResponse`. An unknown ID returns `404`; a slug conflict returns `409`.

#### Create organization settings

`POST /api/v1/organization/{organizationId}/settings`

Request type: `CreateOrganizationSettingsRequest`. Each organization can have settings created once. Omitted values default to `aiTone: PROFESSIONAL`, `autoReplyEnabled: false`, `requireHumanApproval: true`, and an empty `settings` object.

```json
{
  "businessDescription": "Consulting for small businesses.",
  "aiInstructions": "Answer clearly and invite users to book a consultation.",
  "aiTone": "FRIENDLY",
  "autoReplyEnabled": true,
  "requireHumanApproval": false,
  "settings": {}
}
```

Allowed `aiTone` values: `PROFESSIONAL`, `FRIENDLY`, `CONCISE`, `FORMAL`, `CASUAL`. All fields are optional; `settings` is an arbitrary JSON object. Returns `201 Created` with `OrganizationSettingsResponse`. A nonexistent organization returns `404`; settings already created returns `409`.

#### Update organization settings

`PUT /api/v1/organization/{organizationId}/settings`

Request type: `CreateOrganizationSettingsRequest` (same shape and defaults as settings creation). Send the complete settings representation; omitted values reset to the defaults described above, and omitted `settings` becomes an empty object.

```json
{
  "businessDescription": "Consulting for growing businesses.",
  "aiInstructions": "Use a friendly tone and offer a consultation when appropriate.",
  "aiTone": "FRIENDLY",
  "autoReplyEnabled": true,
  "requireHumanApproval": false,
  "settings": {
    "region": "west"
  }
}
```

Returns `200 OK` with the updated `OrganizationSettingsResponse`. An unknown organization or an organization without settings returns `404`.

#### Create a manual lead

`POST /api/v1/organization/lead`

Request type: `CreateLeadRequest`.

```json
{
  "organizationId": "8b5d27f2-27d7-4a49-86d5-252d9c51a7a4",
  "name": "Jamie Taylor",
  "email": "jamie@example.com",
  "phone": "+1-555-0188",
  "source": "REFERRAL"
}
```

Required: `organizationId`, non-blank `name`, and `source`. At least one of `email` or `phone` is required. Email must be valid if provided; phone is limited to 50 characters. Name must fit the lead's first- and last-name fields (maximum 100 characters per part; maximum 201 overall).

Allowed `source` values: `WEBSITE_CONTACTFORM`, `WEBSITE_CHATBOX`, `WHATSAPP`, `INSTAGRAM`, `FACEBOOK`, `REFERRAL`, `MANUAL`, `OTHER`. Returns `201 Created` with `LeadResponse`.

### WhatsApp webhook

The webhook is not enabled for this tracer bullet. Spring Security denies these routes until webhook signature verification and processing are ready. The verification token is generated per application start unless `WHATSAPP_VERIFY_TOKEN` is configured; never send it from frontend code.

### Deployment configuration

- Set `APP_CORS_ALLOWED_ORIGINS` to the exact deployed frontend origin.
- Set database connection values and AI provider API keys through the deployment secret/configuration manager, not frontend code or committed configuration.
- AI output is capped at 768 tokens by default to limit generation time; override with `AI_CHAT_MAX_OUTPUT_TOKENS` if the business requires longer responses. User input remains unconstrained by this application.
- Production exposes only the actuator health endpoint, hides health details, disables SQL formatting and Open Session in View, and uses graceful shutdown.

#### Verify webhook subscription

`GET /api/v1/webhooks/whatsapp?hub.mode=subscribe&hub.verify_token={configuredToken}&hub.challenge={challenge}`

Returns `200 OK` with the challenge as plain text when mode, token, and challenge match; otherwise returns `403 Forbidden` with an empty body.

#### Receive webhook events

`POST /api/v1/webhooks/whatsapp`

Accepts the provider's JSON webhook payload. The current handler processes text messages under `entry[].changes[].value.messages[]`; other message types are ignored. It returns `200 OK` with an empty body.

```json
{
  "entry": [
    {
      "changes": [
        {
          "value": {
            "messages": [
              {
                "id": "wamid.example",
                "from": "15550100",
                "type": "text",
                "text": {
                  "body": "Hello"
                }
              }
            ]
          }
        }
      ]
    }
  ]
}
```

## Shared response shapes

`OrganizationResponse` includes `id`, `name`, `slug`, optional contact/address/branding fields, `timezone`, `currency`, `createdAt`, and `updatedAt`.

`OrganizationSettingsResponse` includes its `id`, `organizationId`, settings values, and timestamps.

`LeadResponse` includes `id`, `organizationId`, optional `externalId`, split `firstName`/`lastName`, contact details, `source`, `status`, and `createdAt`. Lead status values are `ACTIVE`, `CONVERTED`, and `LOST`.

For handled errors, the response body has the form:

```json
{
  "errors": [
    "A request-specific explanation"
  ]
}
```
